# Render hosting adapter

The existing Sites deployment is unchanged. Render runs the same built Worker under Workerd/Miniflare behind a Node HTTP authentication gateway. The gateway supplies verified identity headers; client-supplied identity headers are discarded. All application roles and checks still run inside the Worker.

`render.yaml` provisions one Oregon web service with 512 MB RAM and a 1 GB persistent disk. The database, original files, account password hashes and opaque session records are stored only below `/var/data`. This is a single-instance pilot deployment; disk deployments have a brief interruption and require disk snapshots/backups. It does not use the Sites database or sign-in, so existing Sites records/accounts are not transferred.

Admin email: `admin@javor.example`. The password is generated by Render, never committed. Retrieve it from the service's Environment page. All other accounts require an email-bound application invitation and a password of at least 12 characters. Sessions expire after eight hours; password hashes use scrypt; login attempts are rate limited. Bootstrap initializes the owner before listening publicly. Secrets and uploaded data must not enter source control.

Local verification:

```
npm ci
npm run build
ADMIN_PASSWORD='<local test secret of 20+ characters>' DATA_DIR='.render-data' PORT=5180 npm run start:render
```

Production deployment requires the attached persistent disk. Do not use a free ephemeral service for real records. OpenAI remains optional and unconfigured; add OPENAI_API_KEY to Render's secret environment through secure setup when authorized. Browser OCR, review workflows, ARES and PDF/CSV reports run without it.
